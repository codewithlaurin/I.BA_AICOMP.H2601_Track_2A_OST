# Local Qdrant indexing checkpoint

Pipeline for this step:

`Docling pages.json → page-oriented chunks → multilingual E5 embeddings → Qdrant`

The index is a persistent local folder. No Docker, server or API key is required.
The PDF parser stays separate; this step does not rerun Docling. It uses the
page Markdown exported by the previous step. Keep native `document.json` too:
later structure-aware chunking can use its headings, tables and bounding boxes.

## Files to copy into track_2a

- `scripts/booklet_chunks.py`: Chunk data model, validated page input, and splitting.
- `scripts/vector_index.py`: embedding configuration, Qdrant indexing and search.
- `requirements-vector.txt`: pinned top-level dependencies.
- Optionally `tests/test_booklet_chunks.py`: dependency-free regression checks.

Keep the two scripts together in `scripts/`. Run all commands from `track_2a`.
Your existing parser and downloader need no changes. Use Python 3.11 or newer.

## Install and index one booklet

```sh
uv add -r requirements-vector.txt
uv run python scripts/vector_index.py index --limit 1
```

Default input: `data/booklets/parsed/**/pages.json`.
Default database: `data/qdrant`.
Default collection: `voting_booklets_e5_v1`.

Expect a model download on the first run, followed by a log such as:

```text
Indexed: .../booklet.pdf (32 chunks)
Finished: 1 indexed, 0 unchanged; 32 total chunks
```

The chunk count is illustrative. Empty pages are excluded; long pages produce
multiple parts. Rerun the same command: expect `0 indexed, 1 unchanged` and the
same total count. The model loads and tokenization runs, but unchanged documents
are not embedded again.

To select a particular parsed booklet instead of the first sorted file:

```sh
uv run python scripts/vector_index.py index --input "data/booklets/parsed/example.pdf/pages.json"
```

Replace `example.pdf` with the actual path generated by the parser.

## Search the saved index

Pick a sentence or paraphrase from the booklet you just indexed:

```sh
uv run python scripts/vector_index.py search "Die E-ID ist freiwillig."
```

This example is useful only if an E-ID booklet is in the index. Each result is
printed as JSON with rank, cosine score, original passage, source PDF, document
ID, physical page number, part number and model configuration. Inspect whether
the passage and page actually relate to your query. A score is similarity, not a
truth probability or an ENTAIL/CONTRADICT label.

Optional restriction to a relevant voting booklet:

```sh
uv run python scripts/vector_index.py search "your claim" --document-id SOURCE_SHA256
```

Replace `SOURCE_SHA256` with that booklet's `source_sha256` from `pages.json`.
Without this filter, search covers all indexed booklets. Vote/date filtering
needs verified manifest metadata and is not implemented yet.

After verifying the one-booklet trial, index the collection:

```sh
uv run python scripts/vector_index.py index
```

Storage options go before `index` or `search`; command-specific options go after:

```sh
uv run python scripts/vector_index.py --db data/qdrant --collection voting_booklets_e5_v1 index --batch-size 8
```

## Design choices

- Model: `intfloat/multilingual-e5-small`, 384 dimensions, supporting DE/FR/IT.
  The model revision is pinned in `IndexConfig` to
  `614241f622f53c4eeff9890bdc4f31cfecc418b3`.
- E5 uses `passage: ` for evidence and `query: ` for claims, including non-English
  text. Embeddings are normalized and Qdrant uses cosine similarity.
- Each short page is one chunk. Longer pages split recursively near paragraph
  or whitespace boundaries until every prefixed input fits 480 model tokens,
  including special tokens. E5's limit is 512. No silent page truncation.
- Chunks never cross page boundaries. There is no overlap in this baseline;
  a split can separate a sentence or Markdown table, which should be reviewed
  during error analysis. Raw page text remains in `pages.json`.
- Each chunk stores a deterministic UUID, source PDF SHA-256 as document ID,
  parsed-file fingerprint, physical PDF page, part number and original text.
  Language stays null when absent from the parser; it is not guessed.
- A named vector encodes the model revision and chunking configuration signature.
  A mismatched collection is rejected rather than mixing incompatible vectors.
  To change settings, edit `IndexConfig` and use a new `--collection` name for
  both indexing and search, preserving the baseline.
- Repeated runs skip unchanged documents using their fingerprint and point count.
  Changed parsed output for the same PDF is upserted with stable IDs. Obsolete
  parts of that PDF are removed only after all new parts have been written.
- Indexing stops on a failure and keeps completed work. Rerun the same command
  to finish. A document update is not transactional: after an interrupted update,
  rerun indexing before trusting searches.
- This is incremental ingestion, not directory synchronization. Removing an input
  file does not remove its vectors. A changed original PDF has a new content ID;
  for corpus replacements/removals, build a new collection from the intended set.

Local Qdrant is suitable for this first prototype and allows only one process to
open a given database folder. Run indexing and search sequentially. Do not run
two copies at once. Keep `data/qdrant/` out of Git; commit `pyproject.toml` and
`uv.lock`. Keep backups of inputs and parser exports so the index can be rebuilt.

CPU is the explicit default. You can try `--device mps` on supported Apple hardware
or `--device cuda` on supported NVIDIA hardware; these are optional and unverified
here. Reduce `--batch-size` if embedding runs out of memory. Model downloads need
network access initially. A missing input error means the page exports are not
under the expected directory. An empty-document error means the parsed text must
be inspected before indexing.

## Validation and next checkpoint

Dependency-free checks:

```sh
uv run python -m unittest discover -s tests -v
```

These check chunk text coverage, multilingual characters, page provenance, token
budget callbacks, stable IDs and changed-config signatures. They do not test the
real embedding model or Qdrant runtime. The dependency installation for that test
was not approved in this workspace, and the actual booklet corpus is not present.
Run the indexing/re-indexing/search sequence above in your uv project to verify it.

This search command is a dense-only smoke test, not our final claim workflow.
The target architecture remains BM25 candidates → dense reranking → Apertus.
BM25 candidate retrieval is now available through `sparse_index.py` and the updated
`check_claim.py`; see `BM25.md`. Evaluate retrieval with held-out gold evidence using Recall@5, separately
from classification. Multiple chunks can share one page: deduplicate by document
and page when reporting page-level recall. No retrieval metric is claimed yet.
